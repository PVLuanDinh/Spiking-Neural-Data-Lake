## C34 — P4b's own regression test FAILS in the full suite on unmodified HEAD

**Found 2026-08-04 during specs/010 implementation, not by the audit. Severity: CRITICAL.**

- **Policy**: P4b (the durable lake is part of the brain) + Standing Invariant 5 (verify the verifier)
- **Site**: `tests/test_episode_durability.py`
- **Status**: **PRE-EXISTING — confirmed not caused by this feature's changes.**

### Evidence

```
FAILED tests/test_episode_durability.py::test_episodes_reach_the_lake_and_survive_the_writer
FAILED tests/test_episode_durability.py::test_a_restarted_brain_is_not_amnesic

AssertionError: the brain formed 39 episodes but the lake holds 0.
assert 0 >= 39
  +  where 0 = len([])
```

and

```
>       assert stored > 0
E       assert 0 > 0
```

### Causation established, not assumed

- The two tests **PASS in isolation** (`pytest tests/test_episode_durability.py` -> 6 passed, exit 0).
- They **PASS adjacent** to the file this feature modified
  (`pytest tests/test_cockpit_actuation.py tests/test_episode_durability.py` -> 12 passed).
- They **FAIL in the full suite** on this feature's working tree.
- They **FAIL identically in the full suite on a clean `HEAD` worktree** — same two tests, same
  `..................FFs` position at 41%, with none of this feature's edits present.

The clean-HEAD run is the decisive control. **This feature did not cause it.**

### Why it matters more than an ordinary flake

This is the *exact* defect P4b was written to prevent, reported by the *exact* test written to catch
it. The previous arc's record states the motivating measurement as "59 episodes over 600 ticks with
`persist=True` added **0** lake records"; this failure says "the brain formed **39** episodes but the
lake holds **0**".

So:

1. **P4b is not actually verified in CI.** The test that proves it only passes when run alone. Under
   any full-suite run — which is what CI does — the property is unproven.
2. It is the same family as every other finding this session: a test that **proves the mechanism and
   says nothing about production**. `test_cockpit_actuation` had the identical shape (four green
   tests that never traversed `serve()`), and so did the P4b episode defect itself.
3. The prior handoff recorded the gate as green with "pytest exit 0". Either the suite was not run
   whole, or this regressed afterwards and nothing noticed — **and nothing could have noticed,
   because a green isolated run looks identical to a green suite.**

### Fix direction (NOT yet applied — needs its own diagnosis)

Do **not** simply reorder or isolate the test to make it pass; that would be silencing a check to
make it green (Standing Invariant 2), and it would restore a false green rather than the property.
Diagnose the shared state first: the tests spawn a real second OS process, and something earlier in
the suite leaves the lake, its path, or its append lock in a state where `persist=True` writes land
nowhere. **The honest reading until diagnosed is that episode persistence is order-dependent, which
means P4b's guarantee is currently unproven rather than merely untested.**

**ROOT CAUSE FOUND AND FIXED 2026-08-04.** It was never a test-isolation problem.

`cortex/brain.py` computed persistence as:

    self._persist = (True if persist is None else bool(persist)) and os.environ.get("NORD_PERSIST") != "0"

so **an explicit `make_brain(persist=True)` was silently overridden to False** whenever anything had
put `NORD_PERSIST=0` in the environment. Proven directly: with the var set,
`make_brain(seed=0, persist=True)._persist` returned `False` -- no error, no warning, memories
formed and dropped. The diagnostic added to the assertion showed the smoking gun: correct
`NORD_HOME`, correct `knowledge_path`, correct `_LOG_CACHE` key, lake file present at **8 bytes --
header only**.

The leak: `substrate/cockpit.py:1000` ran `os.environ.setdefault("NORD_PERSIST", "0")` inside its
self-check and never restored it, so one self-check disabled durability for every consumer in the
process afterwards. `home.py:311` had already been fixed for this exact defect ("restored in the
finally, NOT popped") one module over.

**Two fixes, both narrow:**
1. `brain.py` -- the env var is now a DEFAULT for callers who did not specify, never an override of
   callers who did. Verified all three cases: explicit True -> True even under `NORD_PERSIST=0`;
   explicit False -> False; no argument -> False under the off-switch, so hermetic gates are
   unaffected.
2. `cockpit.py` -- scoped: saves the prior value, passes `persist=False` explicitly at the call
   site instead of leaning on a global, and RESTORES in the `finally` (restore, not pop, because
   popping would drop a value the caller set).

**Not fixed by reordering or isolating the test**, which would have restored a false green over a
real P4b violation: a caller asking for durability and silently not getting it is precisely what
P4b exists to prevent.

Tracked as **T061** in tasks.md.
