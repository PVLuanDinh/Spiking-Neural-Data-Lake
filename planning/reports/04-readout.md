# 04 — readout поставленной задачи на фиксированной сети

Дата: 1 ноября 2026 года, America/Chicago.

**Статус: готов в объёме локального диагностического baseline.** Рабочий ориентир
для следующего пилота — существующий **delta-readout на фиксированном резервуаре**.
Он устойчиво решил S0C0, S1C0 с carry и A_c1d на всех четырёх открытых seeds.
Контроли без обучения и с перемешанными метками устойчивого решения не достигли.
R-STDP показал частичные улучшения, но не дал устойчивого baseline по всему набору.
Это не завершение G5, не выбор победителя upstream и не проверка полного Brain.

## Вопрос и понятный результат

Может ли readout научиться отвечать на задачу, если сама сеть уже зафиксирована?
И сохраняет ли сеть раннюю подсказку до момента ответа?

Да, в этом диагностическом опыте. На задаче памяти delta с сохранением состояния
между ходами дал **32/32** на каждом seed. Сброс состояния перед каждым ходом дал
**16/32** у всех шести вариантов. После сброса одна и та же числовая картинка
соответствует двум противоположным ответам: никакое детерминированное чтение этой
картинки не может превысить 50% на проверенном наборе. В carry картинки различаются,
и delta использует эту информацию.

Обучались только читающие ответ веса. Рост и изменение резервуара выключены.

## Фиксированный путь и бюджет

`Problem.teach_epochs/episodes` → `g5_part_d_cells._Drive.walk` →
`g5_readout_cells.pool_features` → сохранённый 256-вектор →
`g5_part_d_cells._learner` **или** `g5_part_d_adaptors.delta` → ответ класса.

Резервуар — существующий `KernelLsmPool`: **256 нейронов**, 64 входа, 2048 входящих
рекуррентных записей, TUNED `{k:8,w:.25,lambda:.9,g:4,T_in:1}`, window=0.
Зафиксированные host-параметры: frac_bits=12, P=1, threads=1.
SHA256 массивов `pre`, `w`, `w_in`, скомпилированных edges и config совпали до/после
каждого feature-path. Вызовов роста, transport, refit или обучения pool нет.

| Условие | Как выполнено |
|---|---|
| carry | Состояние между ходами одного эпизода переносится; после эпизода сбрасывается |
| reset | Штатный сброс перед каждым ходом; границы эпизода те же |
| Общие входы | Все шесть arms читают одни сохранённые векторы своего режима, SHA проверяется |
| Время обучения | 30 полных эпох; ранней остановки и подбора настроек нет |
| Число предъявлений | S0C0/S1C0: 240; A_c1d: 960; frozen: 0 обновлений |
| R-STDP | Part D `_learner`: 2 × 256 синапсов, lr=.06, tau=8, t_post=256, stack=None |
| Delta | Готовый DeltaAdaptor, 256 × 2 beta, float32 CPU, mu=1; все классы с начала, widening=0 |
| Без настройки | Полностью пропускаются teaching-вызовы; весь state остаётся исходным |
| Shuffle | Штатный `_shuffled_labels(seed)`, перестановка внутри каждой эпохи, marginal counts сохранены |
| Dev | Before и после каждой эпохи; read_index=0; метки не передаются reader |
| Final | Одно чтение после 30 эпох и freeze; не выбирает checkpoint |

Начальное состояние совпадает внутри каждого семейства readout. Между семействами
инициализация разная: R-STDP имеет seeded начальные веса, delta — нулевые beta.
Одинаков именно вход **на границе readout**. Внутри R-STDP преобразует его в rank/spike
timing и PSP; delta читает исходный вектор. Сравнение относится к этим целым каналам,
а не изолирует одну формулу обновления от её внутреннего кодирования.

Этап 03 использовал другой штатный канал: 52 текстовых входа, t_post=6 и canonical
PlasticityRuleStack. Его успех не противоречит слабому результату Part D readout здесь.
Ни stack, ни параметры обоих каналов не менялись.

У DeltaAdaptor общий `respond` до первого learn вызывает offline `_settle`. Для
before/frozen и остальных delta-чтений использован его существующий чистый
`_answer(x)`: та же beta-матрица, без first-read изменения `_ready`. Уточнение
раскрыто [до task-run](04-artifacts/implementation-notes.md); shared source не исправлялся.

Для S0C0/S1C0 dev/final — повторные предъявления известных восьми эпизодов, не новые
независимые примеры. Для A_c1d train/dev/final содержат **32/8/12 непересекающихся
полных текстов**, dev/final повторяются четырежды (32/48 ответов). Это новые
сочетания знакомых слов, не новый словарь. `future_d` не читался.

## Память: что показало carry/reset

На каждом seed S1C0/final:

| Режим | Разных probe-векторов | Групп с противоположными целями | Максимум любого детерминированного reader | Delta |
|---|---:|---:|---:|---:|
| carry | 8 | 0 | 32/32 | 32/32 |
| reset | 4 | 4 | 16/32 | 16/32 |

Одинаковые probe-тексты после `jar` и `pen` в reset дают буквально одинаковые
векторы, хотя правильные ответы различаются. В carry ранняя подсказка различима.
Разница delta carry − reset = **+.50** на каждом seed. Это не недостаток ёмкости
reset-reader: нужной информации в его входе уже нет.

У S0C0 delta решает и carry, и reset; R-STDP/reset final = **32,24,24,24 из 32**, без
stable-10. Для одноходовой A_c1d полные paths **и все результаты/состояния readout**
carry/reset побайтно совпали. Границы эпизода и независимый повтор path проверены.

Carry включает мембраны и прочие carriers резервуара. Без отдельного neuter-рекурсии
нельзя приписать весь эффект только рекуррентным весам. Самостоятельная память
полного Brain, длинные задержки и новые задачи памяти здесь не проверены.

## Обучающий сигнал, настраиваемые части и возврат

| Источник | Что получает learner | Что настраивается | Статус здесь |
|---|---|---|---|
| Учитель задачи | Правильная метка train, `interact(x,label)` | Правильный R-STDP нейрон усиливается; ошибочно выбранный ослабляется | Проверено |
| Учитель задачи | Та же train-метка, `DeltaAdaptor.learn` | Только beta readout | Проверено |
| Перемешанный учитель | Переставленные метки с тем же количеством классов | Те же параметры и бюджет | Проверено как контроль |
| Исправление человека / firewall intent | `learn_turn(...,feedback=...)` либо self-label | Штатный текстовый learner/stack | Прочитан код; свежие source positives, не полный Brain |
| Scalar reward | Награда выбранному ответу, `interact(x,float)` | Только выбранный R-STDP нейрон | Код есть; этот arm не запускался |
| BrainProducer | Outcome ±1 → DopamineModulator/RPE → signed factor | R-STDP и внутреннее состояние producer | Код проверен; свежего сравнения producer нет |

Ответ учителя — внешний источник информации; успех этого пилота не показывает,
что Brain сам создаёт достаточный обучающий сигнал. Reservoir weights/input encoder
не обучались. Настоящий no-tune полностью пропускал обновления, не заменялся lr=0.

В upstream уже есть `OwnedPartDReader`/`PosedActor._effect`: читающий нейрон может
сформировать packet и передать его в `port.apply`, а context порта влияет на будущий
вход. Здесь этот путь **прочитан, не запущен и не атрибутирован**. OwnedPartDReader
сейчас обслуживает label-neuron arms; полноценный carrier mutable delta comparator
там не предоставлен. Для применения delta в Brain потребуются корректный carrier,
сохранение в lake, восстановление и отдельная проверка влияния возврата на следующий
ответ. Это зависимости интеграции, а не результат этапа 04.

**Ограниченная задача ремонта R-STDP:** выяснить, почему Part D rank/PSP-канал при
t_post=256 и без stack не достигает стабильности, когда delta на том же reservoir x
решает задачу. Информация в carry представлена, no-tune действительно заморожен,
R-STDP веса обновляются, оценка чистая — неисправность локализована ниже pool, внутри
readout-канала. Разделить представимость именно PSP-кода, параметры обучения и
динамику стабилизации пока нельзя. Следующий ремонт должен проверить эффективный
код и затем менять один фактор по отдельному заранее записанному протоколу.
