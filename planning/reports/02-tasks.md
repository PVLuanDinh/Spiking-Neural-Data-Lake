## Понятный контракт задачи

В (i) восемь эпизодов: все сочетания трёх битов `c, p, q`. Один эпизод — ровно три хода:

```text
jar или pen  →  box  →  oak/elm fox/owl
подсказка       пауза    вопрос из двух слов
```

`jar/pen` обозначают `c=0/1`, `oak/elm` — `p=0/1`, `fox/owl` — `q=0/1`. Ответ — класс `GREET` для бита 0 и `GOAL` для бита 1. Здесь это условные названия классов; маршрут не выполняет действие. Целевая метка есть только у последнего хода. Контекст читается без обучения, учитель корректирует ответ на вопрос. Reader при оценке получает ходы без целевых меток.

| Задача | Что определяет ответ | Что она проверяет | Положительный контроль |
|---|---|---|---|
| S0C0 | `p`: oak → GREET, elm → GOAL | Работает ли простой канал обучения | Canonical learner с правильными метками; рядом lr=0 и shuffle |
| S1C0 | `c`: jar → GREET, pen → GOAL | Доступна ли ранняя подсказка на момент ответа | Explicit history из трёх ходов |
| S0C1 | `p XOR q`: GOAL, если ровно один бит равен 1 | Хватает ли формы текущего представления для нелинейного правила | Существующая frozen expansion H=64 |
| S1C1 | `c XOR p` | Память вместе с нелинейным правилом | Та же expansion вместе с explicit history |

Например, на `pen → box → oak fox` S0C0 требует GREET, а S1C0 — GOAL. Если смотреть только на `oak fox`, отличить этот эпизод от `jar → box → oak fox` невозможно. У обычного reader состояние предыдущих ходов в ответ не входит.

Граница эпизода — единица контракта `Problem.episodes`. История контрольного reader собирается заново из ходов именно этого эпизода; она не переносится между эпизодами. `delay_turns=1` обозначает один промежуточный ход между подсказкой и вопросом, а не один шаг вычислений.

Общий бюджет попытки — максимум **400 эпох**, из текущего `taught_campaign.EPOCHS`; STABLE=10. Положительные варианты (i) останавливались на первых десяти полностью верных validation-чтениях подряд. Все отрицательные контроли и обе попытки C1-d прошли полные 400 эпох. Никакие H/lr/пороги по результатам не подбирались.

Отдельное поле бюджета роста: первое открытие задачи даёт **52** единицы; B11 проверяет нижнюю границу расходов, а не достаточность архитектуры. Последующие значения зависят от положительных расходов решённых задач и beta; в этом опыте этого перехода нет. **Выделено ростом 0 единиц**, потому что механизм роста не вызывался.

### Что означает «решено»

`taught_problems.solved` требует правильного ответа на все предъявления; пустое или неполное чтение не принимается. Validation/future для (i) — по 32 вопроса: четыре предъявления каждого из восьми эпизодов. Устойчивое решение — десять подряд полностью верных validation-чтений. В таблицах эпохи считаются с 1; исходный `first_solved_end` в JSON считается с 0.

Validation/future для (i) предъявляют **те же конечные примеры** в другом порядке. Для этого stateless reader это повторное чтение известного набора, не проверка обобщения на новые слова или сочетания. Оценка идёт без обучения; новый порядок сам по себе независимость данных не создаёт.

Важная проверка критерия: с перемешанными метками S0C0 имела 5 полностью верных чтений, expansion-S0C1 — 16. Ни у одной не было даже двух подряд (максимальная серия = 1). У expansion-shuffle конечная validation и future оказались полностью верными, однако **устойчивого решения нет**. Поэтому одиночный максимум и финальный процент нельзя подменять критерием обучения.

Контроль lr=0 выключает R-STDP-шаг с этой скоростью, но **не замораживает весь stack**: веса действительно изменились. Его корректное чтение — «не выучил», а не «состояние осталось неизменным». Необученный baseline измерен отдельно до первого обучающего предъявления.

Expansion — существующий положительный контроль с другим входным представлением: фиксированная случайная матрица → центрирование по медиане → нелинейный порог → тот же класс learner. На combo медианы берутся только по teach. Его обучение проходит через `interact(features, label)`, тогда как canonical/history используют `learn_turn(text, ..., feedback=label)`. Это не рост, не резервуар и не доказательство успеха того же текстового канала с 64 нейронами.

## Как повторить и как пересчитать

Из корня проекта, новым `--run-id`, чтобы не перезаписать эти записи:

```sh
.venv-01/bin/python -B planning/reports/02-artifacts/run-baseline.py --phase checks --run-id checks-new
.venv-01/bin/python -B planning/reports/02-artifacts/run-baseline.py --phase s0c0 --run-id s0c0-new
.venv-01/bin/python -B planning/reports/02-artifacts/run-baseline.py --phase repeat --run-id repeat-new
cmp planning/reports/02-artifacts/s0c0-new/s0c0.stdout.json planning/reports/02-artifacts/repeat-new/s0c0.stdout.json
```

Это открытые диагностические данные, не новая confirmation. Чтобы повторить остальные уже измеренные блоки, существуют `--phase cells` и `--phase combos`; после провала необходимого положительного контроля сначала разбирается причина, а не запускаются новые seeds или подбор параметров. C1-d требует отдельного будущего рабочего learned-positive, а не повторения до удачи.

Без переобучения существующая проверенная сводка пересчитывается так:

```sh
.venv-01/bin/python -B planning/reports/02-artifacts/summarize.py
```

Она пересчитывает **зафиксированные** каталоги этой работы; новые run-id не подмешиваются автоматически. Raw JSON хранят все ответы и последовательности обучения, в manifest — SHA исходников, протокола и адаптера, версию Python, ОС, времена и хеш результата. Ограничения: 120 секунд на subprocess, 20 минут на блок. Файлы результатов — журнал измерения, не хранилище навыка learner.
